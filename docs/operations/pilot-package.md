**交付版本固定为 0.6.0，并先核对[公开安装包验收](https://github.com/ciceroyang/agentgate/releases/tag/v0.6.0)。** 0.5.0 缺少必需证据判断、清单身份和变化检测的修复，不再作为新企业试点的推荐安装版本；源码验收不能代替公开安装包复核。

## 一句话

**两条路,任选。**

**① 工具层证据记录(单次,5 个工作日,有价)。** 你们手上如果正压着一份客户发来的安全评审或供应商问卷(或一份尽调清单),把里面与 AI 工具相关的条目**原文**给我们(不需要你们的答复)。我们交一份记录:每一条**能查到公开证据**的,答案后面挂上真正读到的证据;查不到的明写「没查到」;并标明哪些属于你们的责任范围、不是我们能出的。价格见下。

**② 免费证据体检(四周)。** 你们先提供一份在用的 MCP server / agent 工具清单,我们用公开来源与已有索引出一份证据报告,不要求私库访问。你们也可以选择自己运行扫描器,再一起配置 CI 策略。默认安排一次一小时复盘;选择策略接入时,另安排半小时确认规则。

## 我们需要的(三件)

1. **一份可以分享的工具名称清单**,不含凭据、内部地址或未获授权分享的信息;不要求仓库访问;
2. **一个联系人**(最好来自平台工程或安全团队,而不是采购);
3. **默认一小时复盘**。选择策略接入时另加半小时,会议合计约一小时半;准备清单、脱敏、运行扫描器和接入 CI 的操作时间另计,按实际范围确认。

## 我们不做的

- **不碰生产系统。** 默认只查公开资料;获得你们同意后才读取脱敏配置或指定源码。我们不运行待检查项目的代码或安装脚本;本地扫描和 CI 接入由你们自己执行。
- **不要凭据。** 不要密钥、不要 token、不要数据库连接串。
- **免费试点不收钱**(上面 ① 那档单次交付是收费的,价格见下)。试点期间没有费用;你们内部是否需要审批由你们决定。结束后如果不继续,报告仍由你们保留。
- **不公开点名。** 结果默认只在你们和我们之间;**能不能引用、怎么引用,由你们决定**,匿名也可以。

## 为什么我们这么做

我们要找的是三种东西:**真实环境里才会出现的问题**、**你们对"这份报告有没有用"的判断**、以及**如果收费你们会不会买**。这三样东西我坐在自己电脑前编不出来。

## 一个诚实的提醒

**先说一条边界,免得你们事后才发现:对着 AI-CAIQ v1.1.0 的 58 条,我们能出证据的是 13 条(我们出证据 13 · 你们自证 41 · 第三方 4)。** 剩下那 41 条是策略、流程与合同,本来就该你们自己答,任何工具都替不了。所以这不是「帮你答问卷」的产品,而是**问卷里那一层只有公开证据能答、别人答不了的部分**。你要是拿着一份问卷期待我们逐条填满,我们做不到——与其等到第 4 周再说,不如现在说。

这个工具很年轻,只有我一个人在用。所以试点里**你们大概率会遇到误报**,也可能遇到我们没覆盖到的东西。遇到就直说——我们更想知道哪里不对,而不是收到一句"还行"。

## 零交接:你们自己跑,我们什么都不收

从 0.1.2 起清单可以完全在你们机器上生成:

```sh
# 使用发布记录中已经复核的精确版本：
npx --yes --ignore-scripts @zhiliangtech/agentgate@0.6.0 discover --format inventory --out tools.json
npx --yes --ignore-scripts @zhiliangtech/agentgate@0.6.0 inventory --input tools.json --out report.html
npx --yes --ignore-scripts @zhiliangtech/agentgate@0.6.0 inventory --input tools.json --framework aicaiq --out report.html
npx --yes --ignore-scripts @zhiliangtech/agentgate@0.6.0 watch --input tools.json --archive ./agentgate-archive
```

（钉住版本是因为我们还在快速迭代;不钉的话,你拿到的行为可能和这份说明不一致。）

- `discover` 不输出 `env`、请求头或启动参数,远程地址只留主机名;读不到或解析不了的配置会单独列出并把退出码置 2——**缺东西的清单不会被当成完整的**;
- 不装任何东西也可以:打开 <https://xn--5kvo87g.com/inventory.html> 粘贴名字,匹配在浏览器里跑;
- `watch` 默认不联网,除非显式给 `--webhook`。

这样交付物不变,只是**你们不需要把任何配置发出来**。仍然建议至少发一份纯名称清单给我们,否则报告里的覆盖范围只能由你们自己判断。

## 材料范围:默认从第 0 层开始

**默认不需要仓库。** 是否继续提供更多材料由你们决定;工具名称本身也可能属于内部信息,请只分享允许外发的内容。

| 层 | 你们可以提供的 | 我们能出什么 | 范围与注意事项 |
| --- | --- | --- | --- |
| **0(默认)** | **在用的 MCP server / agent 工具名称清单** | 查公开注册表、包与已有仓库证据;查不到的明确写 unmeasured | 不要求代码或配置;只分享可外发的名称 |
| 1 | 脱敏后的 `.mcp.json` | 检查版本是否固定、配置中是否有传输认证线索 | 先去掉内部地址和 key;未见认证字段不能证明实际服务没有认证 |
| 2 | **你们自己跑开源扫描器**,审阅并脱敏输出后发给我们 | 基于输出整理报告并说明检查范围;源码留在你们的机器上 | 输出可能含文件路径或代码片段,发送前需要检查 |
| 3 | 经授权的只读仓库材料 | 对约定范围做源码静态检查,未覆盖部分仍写明 | 可选,不作为试点前提;不要求交出密钥或 token |

第 0 层用来判断公开证据是否对你们有用,覆盖率以实际查到的记录为准。需要检查内部配置或源码时,优先选择第 1 或第 2 层,再决定是否扩大范围。
